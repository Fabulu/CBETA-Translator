## The only definition of finished

An entry is remediation-complete only when its current acceptance-bundle hash (`entry.v2.json`, `WORK.md`,
the governing guide/specs, and its dependency fingerprints) has an explicit pass or
reasoned `not_applicable` for every gate below, an independent review, root adjudication, exact KWIC
verification, and parity with the regenerated public artifacts. An old `STATUS=done`, wave merge,
agent report, detector result, or pass attached to an older hash is not sufficient. Translation-XML
repair is a separate project lane and is not counted by this dictionary ledger.

Allowed gate states are `unknown`, `needs_review`, `in_progress`, `pass`, `not_applicable`, and
`blocked`. Automated observations never become semantic passes. Every pass requires reviewer identity,
timestamp, reason, and evidence pointers. `not_applicable` requires a written reason and is allowed only
when the gate's subject is genuinely absent. Evidence, independent-review, and root roles must be
distinct. Editing the entry, WORK evidence, governing rules, or dependencies changes the bundle hash
and invalidates all approvals.

## Required execution order

For an entry or coherent cohort:

1. Regenerate the ledger and claim rows by setting gates `in_progress` in the approvals file.
2. Research with the website sharded index and desktop inverted/KWIC index. Use the source-fingerprinted
   apparatus-clean cache and `zc_batch.py` for multi-query/count/verification work; direct `zc.py` remains the
   parity fallback. For attribution, generate a complete-case packet and map the exact turn before accepting a
   title-owner candidate. The packet is review-only: the fixed 24-case validation found a false title-owner
   accept in an inline quotation, so it cannot write or approve `MasterName`. Final saved evidence must pass the
   same `zc.verify` contract and the human exact-turn check.
3. Draft/revise. Re-read the whole entry after enrichment and re-test the definition and sense split.
4. Run `python3 preflight_semantic_wave.py <wave> --stage owner` before handing completed rows to
   independent review. Every completed row must pass: exact WORK labels, `STATUS=done`, deterministic ID,
   current evidence-gate hash, alias cap, target hygiene, normalized Validation/Curated schema values,
   occurrence-bearing senses, and forbidden-English checks. Fix failures in one owner-side batch; do not
   spend one independent-review cycle per mechanical defect.
5. Evidence reviewer records observations and approvals against the current hash.
6. Independent reviewer searches counterexamples, literal controls, alternate senses, family conflicts,
   and unsupported openings.
7. Root adjudicates the exact current hash.
8. Merge only a coherent accepted cohort, regenerate website artifacts, test, and mark artifact parity.
   Then run `python3 preflight_semantic_wave.py <wave> --stage integration`; registration is forbidden
   until it reports `ready=true`, including 90 current review hashes and exact source/public parity.
9. Regenerate the ledger. Any changed hash reopens the row automatically.

Approval storage may use hash-bound `cohortBundles` when a coherent checkpoint shares evidence reviewer,
independent reviewer, root adjudicator, reports, and gate reasons. This removes duplicated bookkeeping only;
every entry retains its own acceptance-bundle hash, and an explicit per-entry approval overrides a cohort row.

The machine ledger inventories both existing files and all not-yet-built plan/backlog rows. Existing
`entryCount` must never be reported as whole-queue completion; `queueRemaining` governs construction.

The canonical karma filename is `KARMA_DEBATE_BRIEF.md`. If it is not durably present in this build
directory, the three karma/rope entries are blocked before drafting. A temporary `file:///` copy is not
a durable dependency.

This master supersedes historical shortcuts in `STATUS.md`, `CODEX_HANDOFF.md`, and `CODEX_RESUME.md`,
including “accept after N loops.” Use their current live pointers for history and queue context; no old
count or shortcut can mark an entry complete.
